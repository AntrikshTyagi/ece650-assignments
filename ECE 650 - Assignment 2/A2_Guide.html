01Problem statement

Write a C++ program that reads commands from standard input until it sees end-of-file (EOF). The commands describe an undirected, unweighted graph and ask for shortest paths in it. The program has to work interactively: it answers each command as soon as it is read.

The three commands

CommandExampleMeaning
VV 15Start a new graph with vertices 1, 2, …, 15. The number must be greater than one. Everything about the previous graph is forgotten.
EE {<2,6>,<2,8>}The edge set of the current graph. Each edge is <a,b>, edges are separated by commas, the whole set is inside { }, and there is no whitespace inside the braces.
ss 2 10Print one shortest path from vertex 2 to vertex 10, as vertex IDs joined by -, for example 2-8-10.

03Approach, step by step

The steps below follow the order the code was designed in: structure first, then the graph, then the command handlers that sit on top of it.

Step 1 · Plan the structure

a2/ · 6 files

Keep two jobs apart. The graph stores vertices and edges and knows how to find a path. The command layer reads text, checks it, and decides what to print. That way the BFS never deals with strings, and the parser never deals with queues.

Step 2 · Represent the graph

graph.hpp

The graph needs three things: how many vertices there are, which vertices are neighbours, and a way to ask for a path.

graph.hppclass Graph
class Graph {
public:
    using Vertex = long long;
    using Edge = std::pair<Vertex, Vertex>;

    void reset(Vertex n);       // new graph with vertices 1..n
    void invalidate();          // no valid vertex set (e.g. after "V 1")

    bool hasVertices() const { return num_vertices_ > 0; }
    Vertex numVertices() const { return num_vertices_; }
    bool isValidVertex(Vertex v) const { return v >= 1 && v <= num_vertices_; }

    void setEdges(const std::vector<Edge>& edges);
    void clearEdges() { adj_.clear(); }
    std::vector<Vertex> shortestPath(Vertex src, Vertex dst) const;

private:
    Vertex num_vertices_ = 0;
    // Sparse adjacency so a large V does not allocate a huge table.
    std::unordered_map<Vertex, std::unordered_set<Vertex>> adj_;
};

Design choices in this header:

  • Vertex = long long. Signed, so -1 parses and is then rejected as out of range. 64-bit, so large inputs such as V 1000000000 fit.
  • num_vertices_ = 0 means "no graph". Valid graphs always have at least 2 vertices, so 0 is a safe marker. hasVertices() reads it.
  • isValidVertex is the single place that encodes "IDs are 1..n". Both E and s use it, so the rule cannot drift between the two.
  • Adjacency as unordered_map<Vertex, unordered_set<Vertex>>. The map is sparse: only vertices that touch an edge take memory. The inner set removes duplicate edges automatically.

Step 3 · Reset and invalidate

graph.cpp

graph.cppreset / invalidate
void Graph::reset(Vertex n) {
    num_vertices_ = n;
    adj_.clear();
}

void Graph::invalidate() {
    num_vertices_ = 0;
    adj_.clear();
}

Both clear the edges. This is how "a new V forgets all previous information" is enforced: there is no way to start a new vertex set while keeping old edges.

Step 4 · Store edges (self-loops and duplicates)

graph.cpp · Graph::setEdges

graph.cppsetEdges
void Graph::setEdges(const std::vector<Edge>& edges) {
    adj_.clear();
    for (const auto& e : edges) {
        if (e.first == e.second) {
            continue;  // self-loops never shorten a path
        }
        // Sets make <1,2>, <1,2> and <2,1> all the same undirected edge.
        adj_[e.first].insert(e.second);
        adj_[e.second].insert(e.first);
    }
}
  • Undirected: every edge is inserted in both directions.
  • Self-loops (<1,1>) are skipped. The clarification allows ignoring them, and a loop can never be part of a shortest path.
  • Duplicates merge because insert on a set does nothing if the value is already there.
  • The function trusts its input. Range checking is done by the caller first (Step 9), so this function never sees a bad vertex.

Step 5 · Find the shortest path with BFS

graph.cpp · Graph::shortestPath

Every edge has the same cost, so breadth-first search is enough: BFS visits vertices in order of distance from the source, so the first time it reaches the target it has found a shortest path. It runs in O(V + E).

graph.cppshortestPath
std::vector<Graph::Vertex> Graph::shortestPath(Vertex src, Vertex dst) const {
    if (src == dst) {
        return {src};  // a single vertex is a valid path
    }

    // parent[v] = vertex we came from; also serves as the visited set.
    std::unordered_map<Vertex, Vertex> parent;
    std::queue<Vertex> frontier;
    parent[src] = src;
    frontier.push(src);

    bool found = false;
    while (!frontier.empty() && !found) {
        Vertex u = frontier.front();
        frontier.pop();

        auto it = adj_.find(u);
        if (it == adj_.end()) {
            continue;
        }
        for (Vertex w : it->second) {
            if (parent.count(w)) {
                continue;
            }
            parent[w] = u;
            if (w == dst) {
                found = true;  // stop as soon as the target is reached
                break;
            }
            frontier.push(w);
        }
    }

    if (!found) {
        return {};
    }

    std::vector<Vertex> path;
    for (Vertex v = dst; v != src; v = parent.at(v)) {
        path.push_back(v);
    }
    path.push_back(src);
    std::reverse(path.begin(), path.end());
    return path;
}

How it works, in order:

  1. Same vertex. If src == dst, return the one-vertex path right away. This covers the clarification rule, even for isolated vertices.
  2. Start the search. Put src in the queue and record it in parent. Using parent as the visited set saves a second container.
  3. Expand one layer at a time. Take the front vertex, look at its neighbours, and record each unvisited neighbour's parent. A vertex with no edges has no map entry, so adj_.find returns end() and is skipped. Using find instead of adj_[u] also keeps the function const.
  4. Stop early. The moment dst is discovered, break out. The handout suggests this ("terminating once you find the target node").
  5. Rebuild the path. Follow parent links from dst back to src, then reverse. An empty vector means "unreachable", and the caller turns that into an error.

Worked example from the handout: in the V 15 graph, BFS from 2 visits 6, 8 and 5 (distance 1), then reaches 10 from 8 (distance 2). Following parents gives 10 → 8 → 2, reversed to 2-8-10. Going through 6 would also take two hops; which tie BFS picks depends on set order, and the handout allows either.

Step 6 · Read commands until EOF

ece650-a2.cpp · main

ece650-a2.cppmain
int main() {
    Graph g;
    std::string line;

    while (std::getline(std::cin, line)) {
        std::istringstream args(line);
        std::string cmd;
        if (!(args >> cmd)) {
            continue;  // skip blank lines quietly
        }

        if (cmd == "V") {
            handleV(args, g);
        } else if (cmd == "E") {
            handleE(args, g);
        } else if (cmd == "s") {
            handleS(args, g);
        } else {
            reportError("unknown command '" + cmd + "'");
        }
    }
    return 0;
}
  • One line = one command. std::getline reads a full line; an istringstream then splits it into tokens. A bad line can never spill into the next one.
  • EOF ends the loop. getline returns false at EOF (Ctrl-D in a terminal, or the end of a piped file), and the program exits with status 0 and no output.
  • Each handler gets the rest of the line (args) and the graph. The handlers are in an anonymous namespace, so they are private to this file.
  • An unknown command cannot happen in graded tests (syntax is always correct), but reporting it costs nothing and avoids silent failure.

Step 7 · Parse numbers safely, and report errors in one place

ece650-a2.cpp · parseVertex, reportError

ece650-a2.cpphelpers
void reportError(const std::string& msg) {
    std::cerr << "Error: " << msg << std::endl;
}

// Parse a signed integer. Throws std::invalid_argument / std::out_of_range.
Graph::Vertex parseVertex(const std::string& s) {
    std::size_t pos = 0;
    long long v = std::stoll(s, &pos);
    if (pos != s.size()) {
        throw std::invalid_argument("trailing characters");
    }
    return v;
}
  • reportError guarantees the Error: prefix and the stderr stream for every error. A typo in one message can't break the format.
  • std::stoll handles signs. It throws std::out_of_range for a number like 99999999999999999999, which the callers catch and report instead of crashing.
  • The pos check rejects input like 12abc, which stoll alone would read as 12.

Step 8 · Handle V

ece650-a2.cpp · handleV

ece650-a2.cpphandleV
void handleV(std::istringstream& args, Graph& g) {
    std::string tok;
    args >> tok;
    g.invalidate();

    Graph::Vertex n = 0;
    try {
        n = parseVertex(tok);
    } catch (const std::exception&) {
        reportError("invalid number of vertices '" + tok + "'");
        return;
    }
    if (n <= 1) {
        reportError("number of vertices must be greater than one");
        return;
    }
    g.reset(n);
}

g.invalidate() runs before validation on purpose. The clarification says a new V discards all previous graph information. If V 1 left the old graph in place, a following s would wrongly answer from a graph the user meant to replace.

Step 9 · Handle E

ece650-a2.cpp · handleE

ece650-a2.cpphandleE
void handleE(std::istringstream& args, Graph& g) {
    std::string spec;
    args >> spec;

    if (!g.hasVertices()) {
        reportError("no valid vertex set defined for edges");
        return;
    }

    static const std::regex edge_re("<(-?[0-9]+),(-?[0-9]+)>");
    std::vector<Graph::Edge> edges;
    for (auto it = std::sregex_iterator(spec.begin(), spec.end(), edge_re);
         it != std::sregex_iterator(); ++it) {
        const std::smatch& m = *it;
        Graph::Vertex a = 0;
        Graph::Vertex b = 0;
        try {
            a = parseVertex(m[1].str());
            b = parseVertex(m[2].str());
        } catch (const std::exception&) {
            g.clearEdges();
            reportError("edge " + m[0].str() + " has an invalid vertex");
            return;
        }
        if (!g.isValidVertex(a) || !g.isValidVertex(b)) {
            g.clearEdges();
            reportError("edge " + m[0].str() + " references a vertex outside 1.." +
                        std::to_string(g.numVertices()));
            return;
        }
        edges.emplace_back(a, b);
    }

    g.setEdges(edges);
    if (edges.empty()) {
        reportError("empty edge set");
    }
}
  1. Read the whole set as one token. There is no whitespace inside { }, so args >> spec captures {<2,6>,<2,8>,…} in one go.
  2. Need a valid V first. After V 1 there is no vertex set, so the edges can't be checked; report that.
  3. Find each edge with a regex. The pattern <(-?[0-9]+),(-?[0-9]+)> matches one edge and captures both endpoints. -? lets negative IDs through so they are reported as out of range rather than skipped. The regex is static const, so it is compiled once, not on every E.
  4. Check every endpoint, then commit. Edges are collected in a local vector. If any endpoint is bad, nothing is applied: the graph's edges are cleared and one error is printed. Only a fully valid set reaches setEdges.
  5. Empty set. For E {} the loop finds no matches. The (empty) set is applied so the vertices stay usable, and an error is printed as the clarification suggests.

Step 10 · Handle s and format the path

ece650-a2.cpp · handleS

ece650-a2.cpphandleS
void handleS(std::istringstream& args, const Graph& g) {
    std::string tok_a;
    std::string tok_b;
    args >> tok_a >> tok_b;

    if (!g.hasVertices()) {
        reportError("no valid graph defined");
        return;
    }

    Graph::Vertex a = 0;
    Graph::Vertex b = 0;
    try {
        a = parseVertex(tok_a);
        b = parseVertex(tok_b);
    } catch (const std::exception&) {
        reportError("invalid vertex in shortest path query");
        return;
    }
    if (!g.isValidVertex(a) || !g.isValidVertex(b)) {
        reportError("vertex does not exist in the graph (valid range 1.." +
                    std::to_string(g.numVertices()) + ")");
        return;
    }

    std::vector<Graph::Vertex> path = g.shortestPath(a, b);
    if (path.empty()) {
        reportError("no path exists between " + std::to_string(a) + " and " +
                    std::to_string(b));
        return;
    }

    std::ostringstream out;
    for (std::size_t i = 0; i < path.size(); ++i) {
        if (i > 0) {
            out << '-';
        }
        out << path[i];
    }
    // endl flushes so the answer appears immediately in interactive use.
    std::cout << out.str() << std::endl;
}
  • The checks run in order of cost: is there a graph, are the numbers readable, are they in range, then BFS. Each failure prints exactly one error line.
  • const Graph&: a query can never change the graph.
  • Formatting: a dash goes before every vertex except the first, so the line never starts or ends with -. A one-vertex path prints just the number. The path is built in an ostringstream and written with one <<, so a line can't be half-printed.

06Alternative approaches

Each choice above has workable alternatives. None of these are needed, but they are useful to know, and some may fit if the specs change.

A · Other shortest-path algorithms

Dijkstra's algorithm. Needed only if edges had weights. With equal weights it gives the same answer as BFS but costs O((V + E) log V) because of the priority queue.

alternativeDijkstra with std::priority_queue
using P = std::pair<long long, Vertex>;  // (distance, vertex)
std::priority_queue<P, std::vector<P>, std::greater<P>> pq;
std::unordered_map<Vertex, long long> dist;
dist[src] = 0;
pq.push({0, src});
while (!pq.empty()) {
    auto [d, u] = pq.top();   // C++17; in C++11 use .first / .second
    pq.pop();
    if (u == dst) break;      // stop once the target is settled
    if (d > dist[u]) continue;
    for (Vertex w : adj_.at(u)) {
        if (!dist.count(w) || d + 1 < dist[w]) {
            dist[w] = d + 1;
            parent[w] = u;
            pq.push({d + 1, w});
        }
    }
}

Bellman-Ford. Relaxes every edge V−1 times, O(V·E). It handles negative weights, which this problem doesn't have, so it is only slower here.

Bidirectional BFS. Searches from both ends and stops when the frontiers meet. Faster on large graphs, but more code and harder to get the path reconstruction right.

Floyd-Warshall. Precomputes all pairs in O(V³) after each E, making each query instant. Only worth it for tiny graphs with many queries.

B · Other ways to store the graph

Adjacency list as vector<vector<int>>. The textbook choice (CLRS 22.1). Simple and fast, indexed directly by vertex ID. It allocates V+1 slots, so a very large V uses a lot of memory, and duplicates must be removed by hand.

alternativedense adjacency list
std::vector<std::vector<int>> adj(n + 1);   // index 0 unused
adj[a].push_back(b);
adj[b].push_back(a);

std::vector<int> parent(n + 1, -1);         // -1 = not visited
parent[src] = src;

Adjacency matrix (vector<vector<bool>> of size n×n). Duplicates are free and edge lookup is O(1), but memory is O(V²) and BFS has to scan whole rows.

Edge list only. Keep the parsed vector<Edge> and scan it for neighbours during BFS. Very little code, but each step is O(E).

std::set / std::map instead of the unordered versions: neighbours come out sorted, so tie-breaking between equal-length paths becomes predictable (always the smallest ID first).

C · Other ways to parse the edge set

Replace the punctuation with spaces, then read numbers. Turns {<1,2>,<3,4>} into 1 2 3 4 . Short and needs no regex. It relies on input always being well-formed, which the spec guarantees.

alternativereplace-and-stream
for (char& c : spec) {
    if (c == '{' || c == '}' || c == '<' || c == '>' || c == ',') c = ' ';
}
std::istringstream nums(spec);
long long a, b;
while (nums >> a >> b) {
    edges.emplace_back(a, b);
}

Walk the string by hand. Look for each <, read an integer, skip the comma, read another, expect >. The most control, and the fastest, but the longest code.

alternativemanual scan with strtoll
const char* p = spec.c_str();
while ((p = std::strchr(p, '<')) != nullptr) {
    char* end;
    long long a = std::strtoll(p + 1, &end, 10);   // after '<'
    long long b = std::strtoll(end + 1, &end, 10); // after ','
    edges.emplace_back(a, b);
    p = end;
}

sscanf in a loop with the format "<%lld,%lld>%n", using %n to know how far to advance. C-style, compact, but easy to get wrong.

A different regex. R"(<(-?\d+),(-?\d+)>)" using a raw string literal is the same pattern written more readably. std::regex_search in a loop can replace sregex_iterator.

D · Other ways to read commands

Read tokens straight from std::cin instead of whole lines:

alternativetoken-based loop
char cmd;
while (std::cin >> cmd) {
    if (cmd == 'V') { long long n; std::cin >> n; /* ... */ }
    else if (cmd == 'E') { std::string spec; std::cin >> spec; /* ... */ }
    else if (cmd == 's') { long long a, b; std::cin >> a >> b; /* ... */ }
}

Shorter, but a mistake on one line can shift every later read, and a failed >> leaves cin in a fail state that must be cleared. The line-based version is more forgiving.

A switch on the first character (switch (line[0])) instead of comparing strings. Works because every command is one letter.

A dispatch table, std::map<std::string, std::function<void(std::istringstream&, Graph&)>>, which makes adding commands (as later assignments do) a one-line change.

E · Other ways to parse numbers

  • std::stoi (int) instead of std::stoll: fine for small graphs, throws earlier on large values.
  • istringstream >> n with a fail check: no exceptions, but on overflow it sets the stream to failed and you must check for that.
  • std::strtoll: C-style, reports errors through errno and an end pointer instead of exceptions.
  • std::from_chars (C++17): fastest and exception-free, but needs a newer standard than C++11.

F · Other error-handling policies

The clarifications leave some room here. Each of these is defensible:

  • Keep the valid edges of a partly bad E and drop only the bad ones. More lenient, but paths may then be computed on a graph the user didn't intend.
  • Invalidate the whole graph on a bad E, so every later s errors until the next V. Stricter than ours; s v v would then print an error instead of v.
  • Accept E {} silently. The clarification says it "should ideally" be an error, so we report it, but a graph with no edges is still a valid graph.
  • Store self-loops instead of skipping them. BFS would just find the vertex already visited, so results don't change.

G · Other ways to format and print the path

Print the separator after each vertex and stop before the last. Same result, just a different loop shape.

Recursive printing from parent links, which avoids the reverse step:

alternativerecursive print
void printPath(const std::unordered_map<Vertex, Vertex>& parent,
               Vertex src, Vertex v, std::ostream& out) {
    if (v != src) {
        printPath(parent, src, parent.at(v), out);
        out << '-';
    }
    out << v;
}

Very long paths could overflow the call stack, which is why the loop-and-reverse version was used.

'\n' plus an explicit std::flush instead of std::endl. Equivalent here. With a lot of output, flushing once at the end would be faster, but the interactive rule wants each answer to appear right away.

Run BFS from the target instead of the source. Then parent links already point toward the target, and you can print from src forward without reversing.

H · Other code organisation choices

  • Single file. Everything in ece650-a2.cpp. Fine for this size, but the split makes the graph reusable in later assignments, which build on A2.
  • A separate parser module (parser.hpp/.cpp) that turns lines into command structs, so main only dispatches.
  • std::optional<std::vector<Vertex>> (C++17) as the return type of shortestPath, making "no path" explicit instead of relying on an empty vector.
  • Unit tests with Catch2 or GoogleTest as a second CMake target (add_library for the graph, add_executable for tests), run with ctest. Useful for the style mark, but adds build complexity.
  • A shell test script that pipes input files and diffs against expected output files, so all the cases in section 5 can be rerun with one command.
